# Maple Insight

*[English README](README.en.md)*

即時追蹤楓之谷遊戲視窗中的 HP、MP、經驗值與等級。透過 OCR（光學文字辨識）直接讀取畫面上的數值，不打字、不用巨集，也不存取遊戲檔案或記憶體。用它來看看每次練功消耗了多少 EXP/HP/MP、比較不同時段的效率，並取得大略的升級預估時間。

只會「看」你的畫面，絕不會點擊、輸入或對遊戲送出任何操作。

## 功能

- **即時追蹤** — LV/HP/MP/EXP 預設每 0.3 秒更新一次，每項都有進度條。狀態標籤會顯
  示「校準中」「追蹤中」「閒置」「已暫停」或「已停止」，倒數標籤則顯示目前紀
  錄區間還剩多少時間。**開啟程式後預設是「已停止」，不會自動開始記錄** —
  按 **開始** 才會啟動一段新的紀錄；剛開始的一兩秒會顯示「校準中」，先確認讀
  到的最大 HP/MP 與目前經驗值正確，才開始計算變化量。
- **暫停／繼續** — 隨時可以暫停目前的紀錄。暫停期間畫面仍會持續讀取最新數
  值，但不會計入經驗值變化或 HP/MP 損失，計時器也會停止倒數；按繼續會從暫停
  前的進度接著記錄，暫停期間發生的變化不會被算進去。
- **紀錄區間（session）** — 數值會依計時器自動重置（預設 10 分鐘，可調整），
  所以「經驗值變化」永遠代表「從這段紀錄開始到現在」的變化。時間到時預設會自
  動停止並存入歷史紀錄（可在設定關閉，改成自動接著開始下一段）。隨時可以按
  **重新開始** 提前結束目前的區間，預設會存入歷史紀錄（可在設定關閉）。
- **歷史紀錄** — 每段結束的紀錄都會變成一張卡片，顯示開始→結束時間、經驗值
  增加量（含百分比）、楓幣、HP/MP 藥水次數與成本，以及自然／技能回復、藥水回復與
  自然／技能回復預估節省的楓幣。最新的紀錄永遠排在最上面。點卡片標題可以自訂名稱
  （例如「魔法森林」），點卡片右上角的「×」可以刪除該筆紀錄；也可以匯出成 Excel
  友善的 UTF-8 CSV。
- **楓幣統計** — 不需要開啟背包，直接辨識右側撿取訊息中的「楓幣」金額。程式會
  先建立畫面基準，只計算新出現的訊息，避免同一筆通知在多個取樣畫面重複累加；
  OCR 漏讀「楓幣」時，也會用撿取文字與金額格式進行保守補判。
- **藥水與回復統計** — 讀取右下快捷欄位的數量變化，並支援 1–8 個欄位分別設定
  藥水名稱、單價、HP/MP 類型與固定回復量。只會追蹤已啟用的快捷欄位；若尚未啟用
  任何欄位，才會先以「HP/MP 共用、成本 0」統計所有欄位。藥水次數與成本只會在快捷欄位
  數量下降時增加；下降數字會連續確認，並拒絕不合理的大幅跳變，避免喝水動畫或 OCR
  漏位造成大量誤計。回復量只用來把已確認的消耗標記為藥水回復，沒有快捷欄下降的
  自然／技能回復不會被算成喝水。自然／技能回復另以 HP 每點 1.2、MP 每點 2.1 楓幣估算節省。
- **地圖掉落速查** — 自動辨識到地圖後，按「掉落速查」即可在介面內載入該地圖的
  怪物生成與掉落項目；每個怪物可展開／收合，顯示分類、資料來源、已公開的掉落率與
  數量範圍，也能用 ↗ 開啟 [楓憶 MapleMemory](https://morrisrrrrrrr-svg.github.io/)
  的原始頁面。資料是背景載入並在程式執行期間快取，不會阻塞 0.3 秒 OCR 更新；來源
  沒有提供機率時會顯示「—」，不自行推估。
- **解析度與 OCR 自動適應** — 擷取位置會依楓之谷實際 client 視窗像素等比例換算，
  自動處理不同解析度、水平黑邊與視窗調整；數值 OCR 只在結構或信心不足時做放大／
  對比恢復，避免每一幀都使用較慢的偵測 OCR。
- **自動更新** — Windows 打包版啟動後會在背景檢查 GitHub Releases；發現新版本時可
  下載並驗證 SHA-256，確認後由獨立更新程序重新啟動並替換檔案，不會改動使用者的
  設定與歷史紀錄。也可以在「設定」按「檢查更新」。
- **高階工作台介面** — 即時、紀錄、設定分頁改為深色 obsidian／sapphire 卡片層級，
  Live 分頁可捲動，開始後仍可進入半透明橫向 HUD；主畫面保留寬裕間距與可收合的
  掉落速查，不會把所有資訊擠成一面文字。
- **設定**：
  - **視窗縮放** — 用 +/− 按鈕縮放整個視窗。
  - **永遠置頂** — 切換 HUD 是否要蓋在遊戲畫面上方。
  - **懸浮 HUD** — 可設定按下開始後自動隱藏分頁、置頂並套用半透明效果；透明度可
    在 45%–100% 之間調整，按 HUD 按鈕即可還原完整介面。
  - **語言** — 隨時切換中文／英文，即時生效。
  - **紀錄區間** — 每段紀錄多久自動重置一次（1–60 分鐘）。
  - **取樣頻率** — 預設 0.3 秒，可調整為 0.2–1.0 秒；技能使用頻繁時建議維持 0.3 秒。
  - **計時結束時自動停止** — 預設開啟；關閉後計時結束會直接開始下一段，不
    會停下來（回到舊版的行為）。
  - **重新開始時儲存至紀錄** — 預設開啟；關閉後按重新開始只會捨棄目前進
    度，不會留下紀錄。
  - **顯示數據** — 以雙欄清單個別開關等級、HP、MP、經驗值、經驗值增加、每小時
    經驗值、升級預估、HP/MP 損失、楓幣、HP/MP 藥水、回復與節省等欄位，浮動 HUD
    只保留你需要的資訊。
  - **經濟統計** — 可分別關閉楓幣撿取訊息或藥水統計，藥水設定會保存在使用者資料夾。
- **升級預估時間** — 紀錄區間累積幾秒資料後，會依目前的經驗值成長速率估算距
  離下一級還要多久。
- **預估本次經驗值** — 依目前速率推估「照這個速度，這整段紀錄結束時大概會拿
  到多少經驗值」。

## 系統需求

- **Windows** — 需要執行中的 Windows 桌面環境，在 macOS/Linux 上無法實際運作。
  Windows 10 1903 以上會優先使用「Windows Graphics Capture」直接擷取指定的
  楓之谷視窗；即使分析器、瀏覽器或其他視窗浮在前面，也不會把它們的畫面讀進 OCR。
- 安裝好並執行中的楓之谷。
- **遊戲解析度：建議 1366×768 以上。** 實測 1366×768 與 1920×1080 都可正常讀
  取。擷取座標會依實際視窗 client 像素自動換算；視窗越大文字越清楚，辨識也越穩定，
  視窗太小時仍比較容易讀錯。

## 安裝

不需要 Python，也不需要任何安裝步驟 — 只要 `MapleStoryAnalyzer` 資料夾裡的
`MapleStoryAnalyzer.exe` 就夠了。整個資料夾可以放到任何地方（例如
`Desktop\MapleStoryAnalyzer`），但請保持資料夾完整，因為執行檔需要旁邊的其他
檔案才能運作。

## 使用教學

1. 確認楓之谷正在執行、視窗可見。啟動 HUD *之前* 不必是焦點視窗；新版 Windows
   Graphics Capture 啟用後，追蹤期間也不必把遊戲切到最前面。
2. 雙擊 `MapleStoryAnalyzer.exe`。由於這個執行檔沒有數位簽章，Windows 可能會
   跳出 SmartScreen 警告，請點 **更多資訊 → 仍要執行**。
3. 會開啟一個標題為「Maple Insight」的小視窗，永遠置頂，預設停在 **即時**
   分頁。找到遊戲視窗後，LV/HP/MP/EXP 就會在一兩秒內開始顯示數值。
4. 點回遊戲正常遊玩即可，HUD 會在背景持續讀取。隨時可以切到 **紀錄** 分頁查
   看過去的紀錄，或先到 **設定** → **經濟統計** 設定快捷欄位的藥水名稱、單價與
   回復量，再開始練功。若已辨識到地圖，可在 **即時** 分頁按 **掉落速查**，再
   點怪物名稱展開掉落明細。
5. 新版本會在背景通知；也可以到 **設定** → **檢查更新** 手動檢查。下載完成後
   同意重新啟動，程式會自動完成替換。
6. 用完後像一般視窗一樣關掉即可，不需要額外的收尾動作。

## 改用 Python 執行

- **Python 3.10**（透過 `py` 啟動器，例如 `py -3.10`）。
- 安裝好並執行中的楓之谷（同上）。

在專案資料夾開啟終端機，執行一次：

```powershell
py -3.10 -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python .venv\Scripts\pywin32_postinstall.py -install
```

這會建立 `.venv` 資料夾，裡面包含程式所需的一切（OCR 引擎、UI 函式庫、螢幕擷
取函式庫）。只需要做一次，之後用這個指令啟動：

```powershell
.venv\Scripts\python scripts\run_overlay.py
```

不論用 .exe 還是這個指令啟動，程式行為完全相同，上面的使用教學與下面的疑難排
解都同樣適用。

## 發佈新版（維護者）

目前這份程式的 `APP_VERSION` 是 `1.0.9`。每次先把
`src/maple_analyzer/version.py` 改成下一個版本，再提交並推送同名 tag，例如：

```powershell
git tag v1.0.9
git push origin v1.0.9
```

GitHub Actions 會自動安裝依賴、建立 `MapleStoryAnalyzer-v1.0.9-win64.zip`、產生
SHA-256 checksum 並發佈 Release。使用者的打包版下次啟動就能收到更新。

## 疑難排解

- **所有欄位都顯示 `--` 或空白。** 先確認遊戲沒有最小化、沒有被系統切換到
  不再更新畫面的狀態。Windows Graphics Capture 會直接讀指定視窗，不要求它保持
  在最前面；若系統不支援 WGC，程式會退回桌面擷取，此時才需要避免其他視窗遮住
  狀態列。
- **狀態標籤顯示「找不到遊戲視窗」。** HUD 預設尋找標題包含 `新楓之谷` 的視
  窗；如果你的遊戲客戶端視窗標題不同，就會找不到。
- **狀態標籤顯示「狀態列被其他視窗遮擋」。** 這表示目前 Windows Graphics
  Capture 不可用，程式已退回舊的桌面擷取方式；請把遮擋遊戲左下角 LV/HP/MP/EXP
  的視窗移開，過一兩秒就會自動恢復追蹤。WGC 可用時，即使有前景視窗遮住，也不會
  觸發這個狀態。
- **狀態列被工作列蓋住。** 遊戲最大化時，畫面最下方的狀態列可能剛好被 Windows
  工作列擋住。請把遊戲改成視窗模式，或把工作列設成自動隱藏。
- **狀態標籤顯示「遊戲視窗已最小化」。** 請還原遊戲視窗。WGC 不需要它是最上層
  焦點，但最小化或遊戲本身停止繪製時，Windows 沒有可供 OCR 使用的新畫面。
- **某個欄位偶爾讀錯一次，之後又自己恢復。** OCR 偶爾會誤判，通常是戰鬥特效
  或飄血數字剛好蓋住某一幀的狀態列文字。HUD 會沿用該欄位上次讀到的正確數值，
  而不是直接顯示空白，所以單次誤判通常不會被察覺。
- **HP/MP 損失看起來太多、太少，或根本不對。** HP/MP 損失請當成大概的數字，
  不是精確統計。原因有兩個。*取樣頻率*：程式預設每 300 毫秒讀一次狀態列，把前後兩次讀
  數之間的下降量累加起來，所以在同一個取樣間隔內被扣血又補回來的部分完
  全不會被看到，而同一個間隔內挨的好幾下也只會算成一次。*OCR 誤判*：HP/MP 損
  失是累加值，只要有一次讀錯數字（例如 824 讀成 24），就會灌進一筆很大的假損
  失，而且會一直留在這段紀錄裡。經驗值沒有這個問題 — 它只取「結束減開始」，
  中間讀錯一次下一輪就會自己修正回來。如果某段紀錄的 HP/MP 數字明顯離譜，按
  **重新開始** 讓它重新計算即可。
- **數字看起來卡住不動，明明在玩但經驗值沒變。** 先看狀態標籤：如果顯示「追
  蹤中」，代表資料正常更新；如果 HP/MP/EXP 真的都沒變化，那就是真的處於閒置
  狀態，不是 bug。如果標籤顯示錯誤訊息，請參考上面兩點。
- **文字太小、太擠，或視窗大小很奇怪。** 到「設定」→「視窗縮放」，用 +/− 按
  鈕調整。縮放到很小時如果選項被裁切，「設定」分頁也有捲軸可以捲動。
- **不想讓它蓋住遊戲畫面。** 到「設定」關掉「永遠置頂」，或像一般視窗一樣移
  動、縮放它。
- **經驗值偶爾會停住一兩秒才跳動。** 這是正常的：程式會檢查每次讀到的數字是否
  合理，讀錯的那一幀會被丟掉、沿用上一次的數值，等下一幀讀對了再更新。與其顯示
  錯誤的數字，不如慢個半秒。
- **快速連按兩次「重新開始」後，數字看起來怪怪的。** 這是設計行為：1 秒內的
  重複重置會被忽略（避免產生時長為 0 的無意義紀錄），不是 bug。
- **楓幣或藥水沒有增加。** 右側撿取訊息與右下快捷欄位必須保持可見，且不能被其他
  視窗遮住。藥水成本只依快捷欄位數量下降計算；HP/MP 固定回復量只用於確認藥水回復，
  不會在快捷欄位讀不到時自行推算喝水，避免自然回復或補血技能被誤判。每區間預估
  消耗會先收集約 60 秒資料，避免剛開始喝第一瓶時因樣本太短而產生尖峰。
- **掉落速查載入失敗或沒有資料。** 這項功能需要連線到公開的 [楓憶 MapleMemory
  地圖資料庫](https://morrisrrrrrrr-svg.github.io/maps.html)；先確認網路可連線，
  再按一次「掉落速查」。地圖名稱若未辨識成功，可在設定填入地圖手動備援。站方
  沒有提供明確機率的掉落會保留「—」，這代表來源資料未提供數值，不是程式把它當成
  0%。
- **地圖名稱顯示成「第3軍管」而找不到掉落。** 這是小地圖字體把「營」辨識成相近字；
  現在會在編號軍營格式中自動校正，若仍無法辨識可在設定填寫地圖手動備援。
- **剛啟動時視窗沒有立即顯示數值。** OCR 模型會在背景載入，視窗應先保持可操作；
  狀態顯示「正在載入 OCR」時，等待模型完成即可，不需要重複開啟程式。
- **自動更新失敗。** 請確認網路可連線，並確認程式資料夾可寫入；若程式放在
  `Program Files`，Windows 可能需要管理員權限。也可以重新下載 GitHub Release 的
  ZIP，解壓後覆蓋原本的 `MapleStoryAnalyzer` 資料夾；`%LOCALAPPDATA%` 裡的設定與
  歷史紀錄不會被覆蓋。

## 資料與隱私

設定與歷史紀錄不會寫入程式資料夾，而是保存在 Windows 使用者的
`%LOCALAPPDATA%\MapleStoryAnalyzer`（`settings.json` 與 `history.json`）。程式仍然只
讀取螢幕，不讀取遊戲檔案、記憶體，也不會操作遊戲。
